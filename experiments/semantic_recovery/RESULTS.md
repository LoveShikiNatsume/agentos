# 实验 C 结果：快照恢复对重试的影响（2026-10-19，本地 vLLM）

协议见同目录 `README.md`。每题第一次尝试都注入故障（一半执行失败、一半语义失败，冻结在 manifest），`dirty` 与 `snapshot` 只差重试前是否恢复私有上下文，`no_retry` 只尝试 1 次。温度 0，关闭思考，输出上限 4096。差值为 snapshot − dirty 的按题配对 bootstrap 95% CI。完整分析在 `results/` 下。

| 组 | 准确率 | 调用数 | 输入 Token 合计 | 截断 |
|---|---:|---:|---:|---:|
| no_retry | 0% | 223 | 367,801 | 0 |
| dirty | 89% | 573 | 973,225 | 0 |

- 准确率差 −2 pp [−9, +5]；执行失败题 +4 pp [−4, +12]，语义失败题 −8 pp [−20, +2]。
- 每题输入 −416 Token [−480, −356]，约 −4.3%。
- 50 道语义注入全部被校验器发现。`dirty` 组 2 道语义题的重试照抄了残留的错误事实，被重复检测在第二次尝试后停止；`snapshot` 组 0 道。
- 探测集 20 题：dirty 90%、snapshot 85%，差 −5 pp [−20, +10]。

|---|---:|---:|---:|---:|

- 按协议的严格判分：准确率差 −8 pp [−15, −2]，全部来自执行失败题（−16 pp [−30, −4]），语义失败题 0 [0, 0]。每题输入 −312 Token [−343, −282]。
- 事后检查（未预先登记）：差距全部来自格式。失败题的最终答案内容都正确，只是被包在 Markdown 代码块里，严格判分拒绝；最终答案带代码块的题 dirty 4 道、snapshot 12 道。去掉代码块后两组都是 100%，差 0。残留的私有段是裸 JSON，可能让模型照着输出裸 JSON；这只是推测，没有单独验证。
- 50 道语义注入全部被发现，没有出现重复检测停止。
- 校验反馈只说“未通过验收”，不说明是格式问题，所以模型第二次仍然带代码块。

## 结论与限制

- 带反馈的重试把首轮必失败的任务恢复到 87%–96%（严格判分）。快照恢复与保留残留在答案内容上没有可测的差别（Qwen3.5 −2 pp [−9, +5]；Qwen3.8 去掉代码块后 0），输入只少 3%–4%。
- Qwen3.8 上严格判分的显著差异是格式效应，说明校验反馈应当给出可操作的原因（例如“输出必须是裸 JSON”）。
- 失败尝试留下的私有段很短（`dirty` 重试开始时平均 1.7–2.8 段、约 340–565 字符，相对每题 9–10k 输入），对照区分度不够；需要失败尝试留下大量或有迷惑性私有状态的任务。
- 残留错误事实会被照抄（2/50），发生率低。反馈消息要求“重新读源码、核对私有事实”，会削弱残留影响。
- 准确率与完成率在本协议中一致（完成即通过精确答案校验）。
